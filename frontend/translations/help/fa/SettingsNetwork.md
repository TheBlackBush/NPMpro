## شبکه

به NPMpro بگویید کدام پراکسی‌های جلوی آن درباره نشانی واقعی کلاینت قابل اعتمادند. بدون این، لاگ‌ها، فهرست‌های دسترسی و CrowdSec نشانی پراکسی را می‌بینند، نه نشانی بازدیدکننده را.

متغیری که روی کانتینر تنظیم شده باشد بر UI برتری دارد و فیلد را قفل می‌کند (فیلد یک نشان قفل مانند «تنظیم‌شده توسط TRUST_IP» نشان می‌دهد). برای هر چیزی که در کانتینر تنظیم نشده از UI استفاده کنید.

- **IPهای پراکسی مورد اعتماد**: در هر خط یک نشانی IPv4 یا IPv6 یا بازه CIDR، مثلاً `10.0.0.0/8`، `192.168.1.5` یا `fd00::/8`. درخواست‌های این نشانی‌ها می‌توانند IP واقعی کلاینت را در `X-Forwarded-For` منتقل کنند. برای یک load balancer یا تونل که مستقیم جلوی NPMpro است استفاده کنید. پیش‌فرض: خالی (به هیچ‌کس اعتماد نمی‌شود). متغیر: `TRUST_IP` (با فاصله جدا می‌شود). پس از reload nginx که ذخیره اجرا می‌کند اعمال می‌شود.
- **اعتماد به Cloudflare**: بازه‌های IP مربوط به Cloudflare را دریافت می‌کند، به‌طور منظم تازه می‌کند و به آن‌ها اعتماد می‌کند، تا nginx IPهای واقعی کلاینت را پشت Cloudflare ببیند. پیش‌فرض: خاموش. متغیر: `TRUST_CLOUDFLARE`. پس از reload nginx که ذخیره اجرا می‌کند اعمال می‌شود. ابتدا یادداشت‌های مربوط به Cloudflare را در ویکی (Security) بخوانید: قرار دادن Cloudflare جلوی NPMpro هزینه‌های حریم خصوصی و امنیتی دارد.

فقط به نشانی‌هایی اعتماد کنید که خودتان کنترل می‌کنید یا کاملاً به آن‌ها تکیه دارید. یک نشانی مورد اعتماد می‌تواند ادعا کند هر بازدیدکننده‌ای است.

اگر ذخیره در آزمایش nginx شکست بخورد، چیزی ذخیره نمی‌شود و پیام nginx نشان داده می‌شود.

بیشتر در ویکی: Security.
