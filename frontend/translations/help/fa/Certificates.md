## راهنمای گواهی‌ها

### گواهی HTTP

در اعتبارسنجی از طریق HTTP، سرورهای Certbot تلاش می‌کنند از طریق HTTP (نه HTTPS) به دامنهٔ شما دسترسی پیدا کنند. اگر اعتبارسنجی موفق باشد، گواهی صادر می‌شود.

برای این روش باید از قبل یک _میزبان پراکسی (Proxy Host)_ برای دامنهٔ موردنظر ایجاد کرده باشید که از طریق HTTP در دسترس باشد و به همین نصب NPMpro اشاره کند. پس از صدور گواهی می‌توانید Proxy Host را طوری تنظیم کنید که برای اتصال‌های HTTPS نیز از آن استفاده کند. با این حال، برای تمدید خودکار گواهی، دسترسی HTTP باید همچنان برقرار بماند.

این روش از دامنه‌های Wildcard پشتیبانی _نمی‌کند_.

### گواهی DNS

در اعتبارسنجی از طریق DNS باید از افزونهٔ ارائه‌دهندهٔ DNS (DNS Provider) استفاده کنید. افزونه به‌طور موقت رکوردهایی در DNS دامنه ایجاد می‌کند و Certbot با بررسی آن‌ها مالکیت دامنه را تأیید می‌کند. در صورت موفقیت، گواهی صادر می‌شود.

برای درخواست این نوع گواهی لازم نیست از قبل Proxy Host ساخته باشید و Proxy Host نیز نیازی به دسترسی HTTP ندارد.

این روش از دامنه‌های Wildcard پشتیبانی _می‌کند_.

#### اطلاعات احراز هویت ذخیره‌شدهٔ DNS

اطلاعات احراز هویت ارائه‌دهندهٔ DNS (DNS Provider) جدا از گواهی، در زبانهٔ
_اطلاعات احراز هویت DNS_ در صفحهٔ گواهی‌ها ذخیره می‌شود. سپس هر گواهی فقط یکی از
اطلاعات ذخیره‌شده را انتخاب می‌کند، بنابراین چند گواهی می‌توانند از آن‌ها به‌طور مشترک استفاده کنند.

مقادیر محرمانه به‌صورت رمزنگاری‌شده ذخیره می‌شوند و دیگر هرگز نمایش داده نمی‌شوند. هنگام ویرایش، برای حفظ
مقدار ذخیره‌شده، فیلد محرمانه را خالی بگذارید. کلید رمزنگاری در فایل
`/data/npmpro/dns-credentials.key` قرار دارد؛ از آن همراه با پایگاه داده نسخهٔ پشتیبان تهیه کنید، وگرنه
پس از بازیابی، اطلاعات ذخیره‌شده قابل خواندن نخواهند بود.

ارائه‌دهندگانی که فرم ندارند از کادر متنی INI استفاده می‌کنند؛ محتوای فایل
اطلاعات احراز هویت آن ارائه‌دهنده را در آن جای‌گذاری کنید.

### گواهی سفارشی

از این گزینه برای بارگذاری گواهی TLS خود که توسط مرجع صدور گواهی (CA) موردنظر شما صادر شده است استفاده کنید.
