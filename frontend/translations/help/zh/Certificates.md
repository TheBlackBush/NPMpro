## 证书帮助

### HTTP 证书

HTTP 验证的证书表示 Certbot 服务器将尝试通过 HTTP（而非 HTTPS！）访问您的域名，如果成功，它们将为您颁发证书。

使用此方法时，您必须为您的域名创建一个可通过 HTTP 访问并指向此 Nginx 安装的 代理主机。在获得证书后，您可以修改该 代理主机，使其也使用此证书处理 HTTPS 连接。然而，为了证书能够续期，该 代理主机 仍需配置为支持 HTTP 访问。

此过程_不支持_通配符域名。

### DNS 证书

DNS 验证的证书要求您使用一个 DNS 服务商插件。该 DNS 服务商将用于在您的域名下创建临时记录，随后 Certbot 将查询这些记录以确认您是域名所有者，如果成功，它们将为您颁发证书。

请求此类证书前，您无需预先创建 代理主机，也无需将您的 代理主机 配置为支持 HTTP 访问。

此过程_支持_通配符域名。

#### 已保存的 DNS 凭据

DNS 服务商的凭据与证书分开保存，位于证书页面的 _DNS 凭据_ 选项卡中。
证书只需从已保存的凭据中选择一个，因此多个证书可以共用同一凭据。

密钥类信息以加密方式存储，之后不会再显示。编辑凭据时，将某个密钥字段留空即可保留已保存的值。
用于加密的密钥是文件 `/data/npmpro/dns-credentials.key`，请将其与数据库一起备份，
否则恢复后将无法读取已保存的凭据。

没有表单的服务商使用 INI 文本框，请在其中粘贴该服务商凭据文件的内容。

#### 域名

凭据会列出它所管理的域名（DNS 区域），例如 `example.com`。证书页面的**域名**标签页列出您所有凭据的域名。

**域名**字段会建议你的 DNS 凭据中的域名，以及主机和证书已在使用的名称（数据流的名称来自其证书）。仍然可以输入任何其他名称：`添加 <名称>`排在最前，按 Enter 即添加你输入的内容。

使用 DNS 验证时，窗口会建议其域名覆盖所有名称的 DNS 凭据，并说明原因。你可以随时更改，你自己选择的凭据会被保留。

### 自定义证书

使用此选项上传您自己的 TLS 证书，该证书由您自己的证书颁发机构提供。

### 证书颁发机构

向 ACME 服务器申请的证书由其窗口中选择的 CA 签发：实例的 CA（标有“默认”），或管理员在“设置”的证书与 TLS 中通过 **其他 CA** 添加的另一个 CA。列表在 **CA** 列显示每个证书的 CA。证书菜单中的 **重新签发** 会以相同名称向另一个 CA 再次申请；如果失败，当前证书保留。ACME 证书的 **编辑** 用于更改其域名：证书会在同一条目下重新申请，窗口会警告主机仍在使用的名称，失败时不会更改任何内容。
