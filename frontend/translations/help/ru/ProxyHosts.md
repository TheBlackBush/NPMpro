## Что такое прокси-хост?

Прокси-хост это входная точка веб-сервиса. Посетители открывают ваш домен в NPMpro, а NPMpro передаёт запрос сервису, который стоит за ним. Он также может добавить TLS (HTTPS) для сервисов, у которых его нет. Прокси-хосты это самый распространённый сценарий использования NPMpro.

Используйте **Клонировать** в меню хоста, чтобы скопировать хост в новое окно добавления. Копия создаётся без доменных имён, потому что домен может принадлежать только одному включённому хосту.

### Сведения

- **Домены**: имена, которые используют посетители. Обязательное поле. Для нового сертификата подстановочные имена (`*.example.com`) требуют проверки через DNS.
- **Схема**: как NPMpro обращается к сервису: `http://`, `https://`, `grpc://`, `grpcs://`, `path` (отдавать файлы или PHP из папки) или `empty` (без upstream). По умолчанию `http://`. При смене схемы выключаются параметры, которые ей не подходят.
- **Целевой хост / IP / путь**: адрес сервиса. Можно добавить подпуть, например `127.0.0.1/path`. Для `path` укажите папку. Подключайте свои файлы в `/var/www`; папку за её пределами могут использовать только администраторы. Имя, начинающееся с `cu_`, указывает на ваш собственный блок upstream в nginx (см. Load balancing в вики).
- **Целевой порт**: необязательно. Для `path` это версия PHP.
- **Группа**: произвольная метка, которая помогает держать длинные списки в порядке.
- **Параметры** (все по умолчанию выключены):
  - **Отправлять заголовок noindex и блокировать некоторых ботов по User-Agent**: просит поисковые системы не индексировать сайт и блокирует некоторых сканеров.
  - **Отключить CrowdSec AppSec**: отключает CrowdSec AppSec только для этого хоста. Действует, только если AppSec настроен.
  - **Отключить буферизацию запросов** и **Отключить буферизацию ответов**: для upstream http и https. Оставьте буферизацию включённой, если только вы не передаёте потоки или не загружаете большие файлы по быстрому и стабильному каналу. Отключение буферизации запросов также отключает AppSec.
  - **Включить сжатие на стороне upstream**: позволяет сервису сжимать собственные ответы. Оставьте выключенным, если сервису это не нужно. Не для `path` и `empty`.
  - **Включить fancyindex**: показывает список файлов, если в папке нет индексного файла. Только для `path`.
- **X-Frame-Options**: `SAMEORIGIN` (по умолчанию), `DENY`, `none` (убирает заголовок) или `upstream` (оставляет то, что отправляет сервис).
- **Auth Request**: ставит перед хостом проверку входа или ботов (Anubis, Tinyauth, OAuth2 Proxy, VoidAuth, Authelia, Authentik). По умолчанию `none`. **Upstream для Auth Request** необязателен; если пусто, используется значение по умолчанию из раздела Настройки, Внешняя аутентификация.
- **Глобальные списки доступа**: **Публичный** (по умолчанию, без входа) или **Свой**, один или несколько списков доступа.

Websockets всегда включены.

### Свои маршруты

Маршрут отправляет один путь хоста (например, `/api/`) другому сервису. У каждого есть **Включён**, путь с необязательным типом совпадения (`=`, `~`, `~*`, `^~` или `@`), собственные схема, хост, порт, параметры, Auth Request и списки доступа. Его список доступа может быть **Глобальный**, тогда используются списки хоста. Auth Request хоста он не наследует. Добавляйте к пути косую черту в конце, если вам не нужно совпадение по префиксу. Администраторы могут добавить собственную конфигурацию nginx для каждого маршрута кнопкой с шестерёнкой.

### TLS

- **TLS-сертификат**: Нет, запросить новый сертификат или существующий. Параметры ниже требуют сертификата.
- **Сертификат mTLS**: центр сертификации клиентских сертификатов. **Сделать mTLS необязательным** пропускает посетителей без сертификата. **mTLS в обход Auth Request** позволяет посетителям с действительным сертификатом пропустить Auth Request.
- **Всегда HTTPS** перенаправляет HTTP на HTTPS. **Поддержка HTTP/3** включает HTTP/3 (QUIC).
- **HSTS включён (2 года)**: требует «Всегда HTTPS». **HSTS для поддоменов + Preload** требует HSTS.
- Для нового сертификата: **Повторно использовать ключ (не рекомендуется)** и **Проверка через DNS**, с провайдером, учётными данными и временем распространения в секундах.

### Расширенные

Собственная конфигурация nginx для всего хоста (блок server) и для главного маршрута `location /`. Изменять её могут только администраторы.
