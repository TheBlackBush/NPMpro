## CrowdSec

Подключает встроенный в NPMpro bouncer CrowdSec к вашему контейнеру CrowdSec. Каждый запрос к вашим хостам проверяется по решениям локального API CrowdSec (LAPI) и, при заданном URL AppSec, по правилам AppSec. При сохранении настройки применяются сразу перезагрузкой nginx; контейнер не перезапускается.

NPMpro записывает `/data/crowdsec/crowdsec.conf` из этих настроек. Ручные изменения этого файла перезаписываются. `ban.html` и `captcha.html` в той же папке вы можете редактировать сами.

Переменная, заданная для контейнера, имеет приоритет над интерфейсом и блокирует поле: `CROWDSEC_ENABLED`, `CROWDSEC_LAPI_URL`, `CROWDSEC_API_KEY`, `CROWDSEC_APPSEC_URL`.

### Состояние и Проверить подключение

Показывает, загружает ли nginx bouncer и когда NPMpro последний раз связывался с LAPI. **Проверить подключение** проверяет значения из формы: один запрос решений к LAPI с ключом (или клиентским сертификатом TLS) и, при заданном URL AppSec, один запрос к AppSec. Пустое поле ключа использует сохранённый ключ.

При сохранении с включённым bouncer сначала выполняется та же проверка. Если она не удалась, показываются причины, а **Всё равно сохранить** сохраняет настройки всё равно, например когда CrowdSec ещё не запущен.

**Всё равно сохранить** не предлагается, если AppSec не отвечает корректно, для **Если AppSec недоступен** выбрано **Запретить запрос** и интерфейс администратора проверяется: такое сохранение заблокировало бы вам доступ к интерфейсу администратора. Исправьте **Ключ API** или **URL AppSec**, выберите для действия при сбое **Пропустить запрос** или включите **Исключить интерфейс администратора из CrowdSec**.

### Подключение

- **Включить bouncer**: проверяет каждый запрос.
- **URL LAPI**: например `http://127.0.0.1:8080`.
- **Ключ API**: из `docker exec crowdsec cscli bouncers add npmpro`. Хранится в зашифрованном виде и больше не показывается. **Удалить сохранённый ключ** удаляет его.
- **Клиентский сертификат TLS**: вместо ключа файл сертификата и файл ключа в `/data/crowdsec/`; требуется URL LAPI с `https://`. Если задан URL AppSec, поле **Ключ API** показывается и обязательно также при клиентском сертификате TLS, потому что AppSec аутентифицируется ключом API; без него AppSec отклоняет все запросы.
- **Проверять сертификаты TLS**: проверяет сертификат URL LAPI или AppSec с https.

### Блокировка

- **Режим**: live запрашивает LAPI для каждого IP клиента и кэширует ответ на указанное число секунд; stream загружает все решения с указанным интервалом.
- **Ответ на бан**: страница бана (с необязательным кодом состояния, по умолчанию 403), перенаправление или код состояния без страницы.
- **Запасное действие** и **Типы решений**: как обрабатываются решения, которые bouncer не может выполнить, и какие типы применяются.
- **Исключить интерфейс администратора из CrowdSec**: запросы к интерфейсу администратора обходят bouncer и AppSec. Включите это перед использованием AppSec с запретом, чтобы сбой CrowdSec не заблокировал вам доступ.

### Капча

Провайдер (reCAPTCHA, hCaptcha, Cloudflare Turnstile), его ключ сайта и секретный ключ, а также срок действия решённой капчи. Используется для решений типа captcha.

### AppSec

- **URL AppSec**: например `http://127.0.0.1:7422`; пусто отключает AppSec.
- **Если AppSec недоступен**: запрет блокирует каждый проверяемый запрос, пока AppSec недоступен; пропуск оставляет их без проверки.

### Расширенные

Тайм-аут запросов к LAPI, фильтры сценариев, исключённые пути, внутренние запросы, тайм-ауты и параметры AppSec, а также файлы страниц бана и капчи с **Предпросмотром**.

### Потеряли доступ?

Запустите CrowdSec снова или задайте `CROWDSEC_ENABLED=false` для контейнера и пересоздайте его; затем исправьте настройки здесь.
