## Довідка щодо сертифікатів

### HTTP-сертифікат

Під час перевірки сертифіката через HTTP сервери Certbot спробують отримати доступ до ваших доменів через HTTP (не HTTPS!). Якщо перевірка буде успішною, вони видадуть сертифікат.

Для цього методу потрібно створити _проксі-хост_ для відповідних доменів. Він має бути доступним через HTTP і вказувати на цей екземпляр Nginx. Після отримання сертифіката можна налаштувати _проксі-хост_ на використання цього сертифіката для HTTPS-з'єднань. Однак для автоматичного поновлення сертифіката _проксі-хост_ і надалі має бути доступним через HTTP.

Цей спосіб _не підтримує_ підстановчі домени.

### DNS-сертифікат

Для перевірки сертифіката через DNS потрібно використати плагін DNS-провайдера. За допомогою цього плагіна буде створено тимчасові записи у вашому домені. Certbot перевірить ці записи, щоб підтвердити, що домен належить вам, і в разі успішної перевірки видасть сертифікат.

Перед запитом такого сертифіката не потрібно створювати _проксі-хост_ або налаштовувати для нього доступ через HTTP.

Цей спосіб _підтримує_ підстановчі домени.

#### Збережені облікові дані DNS

Облікові дані вашого DNS-провайдера зберігаються окремо від сертифіката, на вкладці
_Облікові дані DNS_ сторінки «Сертифікати». Сертифікат лише обирає один із наборів
збережених облікових даних, тому кілька сертифікатів можуть використовувати їх спільно.

Секрети зберігаються в зашифрованому вигляді й більше ніколи не показуються. Під час редагування облікових даних
залиште секрет порожнім, щоб зберегти попереднє значення. Ключ шифрування зберігається у файлі
`/data/npmpro/dns-credentials.key`. Створюйте його резервну копію разом із базою даних, інакше
після відновлення збережені облікові дані неможливо буде прочитати.

Провайдери без форми використовують текстове поле INI, куди потрібно вставити вміст
файлу облікових даних для цього провайдера.

### Власний сертифікат

Скористайтеся цим варіантом, щоб завантажити власний TLS-сертифікат, виданий вашим центром сертифікації.
