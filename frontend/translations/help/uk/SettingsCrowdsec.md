## CrowdSec

Підключає вбудований у NPMpro bouncer CrowdSec до вашого контейнера CrowdSec. Кожен запит до ваших хостів перевіряється за рішеннями локального API CrowdSec (LAPI) та, за наявності URL AppSec, за правилами AppSec. Під час збереження налаштування застосовуються одразу перезавантаженням nginx; контейнер не перезапускається.

NPMpro записує `/data/crowdsec/crowdsec.conf` із цих налаштувань. Ручні зміни цього файлу перезаписуються. Сторінки блокування та капчі вибираються в розділі **Налаштування**, **Цільові сторінки**; там само можна вставити або завантажити власну сторінку.

Змінна, задана для контейнера, має пріоритет над інтерфейсом і блокує поле: `CROWDSEC_ENABLED`, `CROWDSEC_LAPI_URL`, `CROWDSEC_API_KEY`, `CROWDSEC_APPSEC_URL`.

### Стан і Перевірити підключення

Показує, чи завантажує nginx bouncer і коли NPMpro востаннє зв'язувався з LAPI. **Перевірити підключення** перевіряє значення з форми: один запит рішень до LAPI з ключем (або клієнтським сертифікатом TLS) та, за наявності URL AppSec, один запит до AppSec. Порожнє поле ключа використовує збережений ключ.

Під час збереження з увімкненим bouncer спочатку виконується та сама перевірка. Якщо вона не вдалася, показуються причини, а **Усе одно зберегти** зберігає налаштування попри це, наприклад коли CrowdSec ще не запущено.

**Усе одно зберегти** не пропонується, якщо AppSec не працює коректно, для **Коли AppSec недоступний** вибрано **Відхилити запит** і для **Інтерфейс адміністратора і CrowdSec** вибрано **Перевіряється як усі хости**: таке збереження заблокувало б вам доступ до інтерфейсу адміністратора. Виправте **Ключ API** або **URL AppSec**, виберіть для дії при збої **Пропустити запит** або виберіть для **Інтерфейс адміністратора і CrowdSec** варіант **Лише бани** чи **Виключено**.

### Підключення

- **Увімкнути bouncer**: перевіряє кожен запит.
- **URL LAPI**: наприклад `http://127.0.0.1:8080`.
- **Ключ API**: із `docker exec crowdsec cscli bouncers add npmpro`. Зберігається в зашифрованому вигляді й більше не показується. **Видалити збережений ключ** видаляє його.
- **Клієнтський сертифікат TLS**: замість ключа файл сертифіката і файл ключа в `/data/crowdsec/`; потрібен URL LAPI з `https://`. Якщо задано URL AppSec, поле **Ключ API** показується й обов'язкове також за клієнтського сертифіката TLS, бо AppSec автентифікується ключем API; без нього AppSec відхиляє всі запити.
- **Перевіряти сертифікати TLS**: перевіряє сертифікат URL LAPI або AppSec з https.

### Блокування

- **Режим**: live запитує LAPI для кожної IP-адреси клієнта та кешує відповідь на вказану кількість секунд; stream завантажує всі рішення із вказаним інтервалом.
- **Відповідь на бан**: сторінка бану (з необов'язковим кодом стану, типово 403), перенаправлення або код стану без сторінки.
- **Запасна дія** і **Типи рішень**: як обробляються рішення, які bouncer не може виконати, і які типи застосовуються.
- **Інтерфейс адміністратора і CrowdSec**: **Перевіряється як усі хости** застосовує до інтерфейсу адміністратора бани та AppSec. **Лише бани** застосовує бани та captcha, але не AppSec, і збій CrowdSec не заблокує вам доступ. **Виключено** нічого не перевіряє. Доступ закрито рішенням про бан або капчу? Див. **Втратили доступ?** нижче.

### Капча

Провайдер (reCAPTCHA, hCaptcha, Cloudflare Turnstile), його ключ сайту й секретний ключ, а також строк дії розв'язаної капчі. Використовується для рішень типу captcha.

### AppSec

- **URL AppSec**: наприклад `http://127.0.0.1:7422`; порожньо вимикає AppSec.
- **Коли AppSec недоступний**: відхилення блокує кожен перевірюваний запит, поки AppSec недоступний; пропуск залишає їх без перевірки.

### Розширені

Тайм-аут запитів до LAPI, фільтри сценаріїв, виключені шляхи, внутрішні запити, а також тайм-аути та параметри AppSec.

### Втратили доступ?

Рішення про бан або капчу для вашого IP: виконайте в контейнері CrowdSec `cscli decisions delete --ip <ваш IP>`. Рішення зі списку блокування (спільного списку спільноти або списку з консолі CrowdSec) повернеться під час наступного завантаження, тож також додайте свій IP до allowlist (CrowdSec 1.6.6 або новіший): `cscli allowlists create npmpro-admins -d "admin IPs"`, потім `cscli allowlists add npmpro-admins <ваш IP>`.

CrowdSec недоступний: запустіть його знову. Немає доступу до CrowdSec: задайте `CROWDSEC_ENABLED=false` для контейнера й створіть його заново, виберіть тут **Виключено** для **Інтерфейс адміністратора і CrowdSec** (або видаліть рішення), виправте налаштування, потім приберіть змінну й знову створіть контейнер.
