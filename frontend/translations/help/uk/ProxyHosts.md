## Що таке проксі-хост?

Проксі-хост це вхідна точка вебсервісу. Відвідувачі відкривають ваш домен у NPMpro, а NPMpro передає запит сервісу, що стоїть за ним. Він також може додати TLS (HTTPS) для сервісів, які його не мають. Проксі-хости це найпоширеніший сценарій використання NPMpro.

Використовуйте **Клонувати** в меню хоста, щоб скопіювати хост у нове вікно додавання. Копія створюється без доменних імен, тому що домен може належати лише одному ввімкненому хосту.

### Відомості

- **Домени**: імена, які використовують відвідувачі. Обов'язкове поле. Для нового сертифіката підстановні імена (`*.example.com`) потребують перевірки через DNS.
- **Схема**: як NPMpro звертається до сервісу: `http://`, `https://`, `grpc://`, `grpcs://`, `path` (віддавати файли або PHP з теки) або `empty` (без upstream). За замовчуванням `http://`. Зміна схеми вимикає параметри, які їй не підходять.
- **Цільовий хост / IP / шлях**: адреса сервісу. Можна додати підшлях, наприклад `127.0.0.1/path`. Для `path` вкажіть теку. Підключайте свої файли в `/var/www`; теку поза ним можуть використовувати лише адміністратори. Ім'я, що починається з `cu_`, вказує на ваш власний блок upstream у nginx (див. Load balancing у вікі).
- **Порт перенаправлення**: необов'язково. Для `path` це версія PHP.
- **Група**: довільна мітка, що допомагає тримати довгі списки впорядкованими.
- **Параметри** (усі за замовчуванням вимкнені):
  - **Надсилати заголовок noindex і блокувати деяких ботів за User-Agent**: просить пошукові системи не індексувати сайт і блокує деяких сканерів.
  - **Вимкнути CrowdSec AppSec**: вимикає CrowdSec AppSec лише для цього хоста. Діє, лише якщо AppSec налаштовано.
  - **Вимкнути буферизацію запитів** і **Вимкнути буферизацію відповідей**: для upstream http і https. Залиште буферизацію ввімкненою, якщо тільки ви не передаєте потоки або не завантажуєте великі файли швидким і стабільним каналом. Вимкнення буферизації запитів також вимикає AppSec.
  - **Увімкнути стиснення на боці upstream**: дозволяє сервісу стискати власні відповіді. Залиште вимкненим, якщо сервісу це не потрібно. Не для `path` і `empty`.
  - **Увімкнути fancyindex**: показує список файлів, якщо в теці немає індексного файлу. Лише для `path`.
- **X-Frame-Options**: `SAMEORIGIN` (за замовчуванням), `DENY`, `none` (прибирає заголовок) або `upstream` (залишає те, що надсилає сервіс).
- **Auth Request**: ставить перед хостом перевірку входу або ботів (Anubis, Tinyauth, OAuth2 Proxy, VoidAuth, Authelia, Authentik). За замовчуванням `none`. **Upstream для Auth Request** необов'язковий; якщо порожньо, використовується значення за замовчуванням із розділу Налаштування, Зовнішня автентифікація.
- **Глобальні списки доступу**: **Загальнодоступний** (за замовчуванням, без входу) або **Власний**, один чи кілька списків доступу.

Websockets завжди ввімкнені.

### Власні маршрути

Маршрут надсилає один шлях хоста (наприклад, `/api/`) іншому сервісу. У кожного є **Увімкнено**, шлях з необов'язковим типом збігу (`=`, `~`, `~*`, `^~` або `@`), власні схема, хост, порт, параметри, Auth Request і списки доступу. Його список доступу може бути **Глобальний**, тоді використовуються списки хоста. Auth Request хоста він не успадковує. Додавайте до шляху похилу риску в кінці, якщо вам не потрібен збіг за префіксом. Адміністратори можуть додати власну конфігурацію nginx для кожного маршруту кнопкою із шестірнею.

### TLS

- **TLS-сертифікат**: Немає, запросити новий сертифікат або наявний. Параметри нижче потребують сертифіката.
- **Сертифікат mTLS**: центр сертифікації клієнтських сертифікатів. **Зробити mTLS необов'язковим** пропускає відвідувачів без сертифіката. **mTLS в обхід Auth Request** дозволяє відвідувачам із чинним сертифікатом пропустити Auth Request.
- **Завжди HTTPS** перенаправляє HTTP на HTTPS. **Підтримка HTTP/3** вмикає HTTP/3 (QUIC).
- **HSTS увімкнено (2 роки)**: потребує «Завжди HTTPS». **HSTS для піддоменів + Preload** потребує HSTS.
- Для нового сертифіката: **Повторно використовувати ключ (не рекомендується)** і **Перевірка через DNS**, з провайдером, обліковими даними та часом поширення в секундах.

### Розширені налаштування

Власна конфігурація nginx для всього хоста (блок server) і для головного маршруту `location /`. Змінювати її можуть лише адміністратори.
