## 접근 정책이란?

접근 정책은 프록시 호스트를 보호합니다. 방문자에게 사용자 이름과 비밀번호를 요구하거나(기본 인증), IP 주소로 방문자를 허용 또는 거부하거나, 둘 다 할 수 있습니다. 자체 로그인이 없는 서비스에 유용하며, 알 수 없는 클라이언트를 막고 싶을 때도 도움이 됩니다.

하나의 목록을 여러 프록시 호스트와 위치에서 사용할 수 있습니다.

### 세부 정보

- **이름**: 필수입니다.
- **조건 중 하나라도 충족**(기본값은 꺼짐): 규칙 또는 유효한 사용자 중 하나라도 일치하면 방문자가 통과합니다. 꺼져 있으면 둘 다 통과해야 합니다. 이 호스트에서는 Auth Request도 건너뜁니다.
- **인증 정보를 원본 서버로 전달**(기본값은 꺼짐): 방문자의 `Authorization` 헤더를 서비스로 그대로 보냅니다. 꺼져 있으면 로그인 정보는 NPMpro 안에서만 사용됩니다.

### 인증

사용자 이름과 비밀번호를 추가합니다. 사용자 이름은 목록 안에서 고유해야 하며 `:`를 포함할 수 없습니다. 목록을 편집할 때 저장된 비밀번호를 유지하려면 비워 두세요.

### 규칙

규칙은 IP 주소, CIDR 범위(`192.168.1.0/24`, `2001:db8::/32`) 또는 `unix:`를 허용하거나 거부합니다. 규칙은 나열한 순서대로 적용되며 처음 일치하는 규칙이 우선합니다. 구체적인 규칙을 먼저 두세요. 마지막 `all` 규칙은 목록을 닫으며 허용 또는 거부로 설정합니다. 다른 규칙이 하나 이상 있을 때만 추가됩니다. 목록에는 사용자 또는 규칙이 하나 이상 있어야 합니다.

### 프록시 호스트에서 사용

프록시 호스트의 세부 정보 탭에 있는 **전역 접근 정책**에서 목록을 선택합니다. **누구나 접근 가능**(목록 없음) 또는 **사용자 지정**입니다. 사용자 지정 위치에서는 **전역**(호스트의 목록), **누구나 접근 가능** 또는 자체 **사용자 지정** 목록을 사용할 수 있습니다.

하나의 호스트나 위치에 여러 목록을 연결할 수 있습니다. 목록은 표시된 순서대로 위에서 아래로 확인되며, 위아래로 옮길 수 있습니다. **조건 중 하나라도 충족**과 **인증 정보를 원본 서버로 전달**은 첫 번째 목록에서만 적용됩니다. CrowdSec을 사용하면 차단된 IP는 비밀번호 입력 전에 차단 페이지를 봅니다.

자세한 내용은 위키를 참조하세요: Host options.
